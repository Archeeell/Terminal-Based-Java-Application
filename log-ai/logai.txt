[MAHASISWA]
saya punya kode untuk class pelanggan ini. Apakah class ini sudah menerapkan encapsulation dgn benar?

public class Pelanggan {
    String nama;
    String nomorTelepon;
    String alamat;

    // constructor
    public Pelanggan(String nama, String nomorTelepon, String alamat) {
        this.nama = nama;
        this.nomorTelepon = nomorTelepon;
        this.alamat = alamat;
    }

[CLAUDE AI]
Kode Anda sudah memiliki getter dan setter, yang merupakan langkah
yang baik menuju encapsulation. Namun, ada satu masalah utama:

**Atribut belum bersifat private.**

Saat ini Anda menulis:
```java
String nama;
String nomorTelepon;
String alamat;
```

Tanpa access modifier, atribut-atribut ini bersifat *package-private*,
artinya kode lain dalam package yang sama bisa langsung mengaksesnya
tanpa melewati getter/setter. Ini melanggar prinsip encapsulation.

**Perbaikan yang disarankan:**
```java
private String nama;
private String nomorTelepon;
private String alamat;
```

Dengan kata kunci `private`, atribut hanya bisa diakses dari dalam
class itu sendiri, dan kode luar harus menggunakan getter/setter.

Selain itu, Anda bisa memperkuat encapsulation dengan menambahkan
validasi pada setter, misalnya:
```java
public void setNama(String nama) {
    if (nama != null && !nama.trim().isEmpty()) {
        this.nama = nama;
    } else {
        System.out.println("Nama tidak boleh kosong.");
    }
}
```

Apakah ada bagian lain yang ingin Anda tanyakan?

[MAHASISWA]
apakah ada masalah pada constructor class pesanan yg saya buat ini ?

public Pesanan(String idPesanan, Pelanggan pelanggan, String jenisLayanan, double beratCucian) {
    this.idPesanan = idPesanan;
    this.pelanggan = pelanggan;
    this.jenisLayanan = jenisLayanan;
    this.beratCucian = beratCucian;
    this.status = "masuk";
    hitungBiaya();
}

void hitungBiaya() {
    if (jenisLayanan == "express") {
        totalBiaya = beratKucian * HARGA_EXPRESS;
    } else {
        totalBiaya = beratKucian * HARGA_REGULER;
    }
}

[CLAUDE AI]
Bagus Anda bertanya! Ada beberapa masalah yang perlu diperhatikan:

**1. Bug Kritis: Perbandingan String dengan ==**

Ini adalah bug yang sangat umum di Java. Baris ini salah:
```java
if (jenisLayanan == "express") {
```

Operator `==` membandingkan *referensi memori*, bukan nilai String.
Di Java, dua String dengan isi yang sama bisa memiliki referensi yang
berbeda. Gunakan `.equals()`:
```java
if (jenisLayanan.equals("express")) {
```
atau lebih aman lagi (menghindari NullPointerException):
```java
if ("express".equals(jenisLayanan)) {
```

**2. Metode hitungBiaya() sebaiknya private**
Karena ini adalah logika internal class, method `hitungBiaya()`
tidak perlu diakses dari luar. Tambahkan `private`.

**3. Saran desain: Gunakan enum untuk jenis layanan**
Menggunakan String bebas untuk `jenisLayanan` rawan typo. Pertimbangkan:
```java
public enum JenisLayanan {
    REGULER("Reguler", 5000),
    EXPRESS("Express", 10000);
    // ...
}
```
Dengan enum, compiler akan membantu Anda menghindari nilai yang tidak valid.

public Pesanan cariPesanan(String idPesanan) {

[CLAUDE AI]
Ini adalah bug yang sama seperti yang saya sebutkan sebelumnya —
**perbandingan String dengan `==`!**

```java
// SALAH:

// BENAR:
if (daftarPesanan.get(i).getIdPesanan().equals(idPesanan))
```

```java
for (Pesanan p : daftarPesanan) {

        return p;

```
Lebih bersih dan lebih mudah dibaca.

apakah desain class saya bisa diperbaiki agar lebih sesuai prinsip oop?
apakah ada yang kurang?

[CLAUDE AI]
Secara umum desain Anda sudah cukup baik untuk tingkat pemula!
Berikut beberapa saran peningkatan:

**1. Gunakan interface List, bukan ArrayList secara langsung**
```java
// Kurang fleksibel:
ArrayList<Pesanan> daftarPesanan = new ArrayList<>();

// Lebih baik (programming to interface):
List<Pesanan> daftarPesanan = new ArrayList<>();
```

**2. Tambahkan constructor pada KasirLaundry**
Meskipun Java memberikan default constructor, lebih baik eksplisit:
```java
public KasirLaundry() {
    this.daftarPesanan = new ArrayList<>();
    this.counterID = 1;
}
```

**3. Konstanta sebaiknya final**
```java
// Fase 1 Anda:
static double HARGA_REGULER = 5000;

// Lebih baik:
static final double HARGA_REGULER = 5000;
```
Tanpa `final`, nilai konstanta bisa diubah dari luar, yang berbahaya.

**4. Pemformatan output yang lebih baik**
Untuk angka rupiah, gunakan format yang lebih mudah dibaca:
```java
System.out.printf("Total Biaya: Rp %,.0f%n", totalBiaya);
// Output: Total Biaya: Rp 25.000 (bukan 25000.0)
```

**5. Penanganan input tidak valid**
Di Main.java, jika pengguna mengetik huruf saat diminta angka,
program akan crash. Tambahkan try-catch untuk InputMismatchException.

[MAHASISWA]
apakah ad masalah yg kamu temukan dengan bgaimana cara saya menggunakan scanner di Main.java? 
kadang setelah nextInt() saya harus menambahkan sc.nextLine() extra.

[CLAUDE AI]
Anda mengidentifikasi masalah yang sangat umum! Ini penjelasannya:

Ketika Anda memanggil `scanner.nextInt()`, Scanner membaca angka
tetapi **meninggalkan karakter newline `\n`** di buffer.

Saat `nextLine()` dipanggil berikutnya, ia membaca sisa buffer
(yang hanya berisi `\n`) dan langsung selesai — seolah pengguna
langsung menekan Enter.

**Solusi:**
```java
int angka = scanner.nextInt();
scanner.nextLine(); // "buang" newline sisa
String teks = scanner.nextLine(); // ini baru baca input pengguna
```

Pola ini perlu diterapkan **setiap kali** Anda memanggil `nextInt()`,
`nextDouble()`, atau `nextLong()` yang diikuti oleh `nextLine()`.

Alternatif yang lebih aman: bungkus dalam method helper:
```java
private static int bacaAngka(Scanner scanner, String prompt) {
    System.out.print(prompt);
    try {
        int nilai = scanner.nextInt();
        scanner.nextLine(); // bersihkan buffer
        return nilai;
    } catch (InputMismatchException e) {
        scanner.nextLine(); // buang input tidak valid
        return -1; // nilai default jika input salah
    }
}
```
